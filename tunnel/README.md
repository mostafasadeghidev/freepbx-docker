# تونل — فقط اگر لازمش داری

این پوشه برای **یک** وضعیت است:

> سرورِ تلفن خارج از کشور است، و اپراتورِ تلفن فقط با یک آدرسِ داخلِ کشور تماس
> رد و بدل می‌کند.

اگر سرورِ تو و اپراتورت در یک کشورند، این پوشه به کارت نمی‌آید. تونل را روشن
نکن و دیگر به آن فکر نکن.

---

## اول یک تصمیم: کدام سمت گوش می‌دهد؟

این تنها سؤالِ مهمِ این پوشه است و جوابش به **سمتِ داخلِ کشور** بستگی دارد، نه
به سرور.

| | **سرور گوش می‌دهد** (`compose.tunnel-server.yml`) | **سرور زنگ می‌زند** (پروفایلِ `tunnel`) |
|---|---|---|
| سمتِ ایران | روتر یا هر چیزی که آدرسِ عمومی **ندارد** | سروری که آدرسِ عمومی **دارد** |
| چه کسی وصل می‌شود | روتر به سرور | سرور به آن سرویس |
| پورت روی سرور | باز می‌شود | لازم نیست |

**تقریباً همیشه حالتِ اول درست است.** خطِ خانه یا اداره — و مخصوصاً سیم‌کارت —
پشتِ NATِ اپراتور است و از بیرون قابلِ دسترس نیست. اندازه‌گیری‌شده روی خطِ
نویسنده: هم سیم‌کارت و هم PPPoE آدرسی از فضای `100.64.0.0/10` داشتند — یعنی
NATِ اپراتور، و هیچ‌کدام از بیرون قابلِ صدا زدن نبود.

---

## حالتِ «سرور گوش می‌دهد» — قدم به قدم

**ساده‌ترین راه:** `./setup.sh` را اجرا کن و به سؤالِ تونل `listen` جواب بده.
پورتِ آزاد را خودش پیدا می‌کند، کلیدها و رمز و `server.conf` و `iroute` را
می‌سازد، و خطِ آمادهٔ روتر را چاپ می‌کند. آزموده‌شده از اول تا آخر: روتری در
ایران با همان رمزی که `setup.sh` ساخته بود وصل شد و سرورِ SIPِ اپراتور از داخلِ
کانتینرِ تلفن جواب داد.

**روی نصبی که از قبل کار می‌کند:** `./tunnel/listen.sh --net 203.0.113.0/24`
(و برای روترِ دوم `--user office`). همان فایل‌ها را می‌سازد، `.env` را به‌روز
می‌کند، پورت را پیش از روشن کردن می‌سنجد و صبر می‌کند تا OpenVPN واقعاً گوش بدهد.
اجرای دوباره‌اش بی‌خطر است: رمزِ کاربرِ موجود و CA عوض نمی‌شوند. آزموده‌شده روی
سرورِ تست: اجرای دوم هیچ کانتینری را از نو نساخت، و کاربرِ دوم یک `route` و یک
`ccd` تازه گرفت بی‌آنکه به اولی دست بخورد.

قدم‌های زیر همان کار است، دستی — برای وقتی که بخواهی بدانی زیرِ آن چه می‌گذرد.

### روی سرور

```bash
./tunnel/make-server-pki.sh                      # یک بار: CA و کلیدِ سرور
printf 'router:یک-رمزِ-بلند\n' > tunnel/users
cp tunnel/server.conf.example tunnel/server.conf # سه خطِ ① ② ③ را بخوان
mkdir -p tunnel/ccd
printf 'iroute 203.0.113.0 255.255.255.0\n' > tunnel/ccd/router
```

بعد در `.env`:

```
TUNNEL_PORT=1194
COMPOSE_FILE=compose.yml:compose.tunnel-server.yml
```

و:

```bash
./apply.sh
```

`COMPOSE_FILE` در `.env` یعنی هر `docker compose`ِ ساده — از دستِ تو، از
`doctor.sh`، یا از هر ابزاری که پروژه را می‌خواند — کلِ مجموعه را برمی‌دارد. اگر
یک بار بدونِ فایلِ تونل `up -d` بزنی، تونل **پاک می‌شود**.

> ⚠️ روی ماشینی که Coolify دارد، پورتِ تونل را ۴۴۳ نگذار. آنجا ۴۴۳ (و
> ۴۴۳/udp برای HTTP/3) دستِ Traefik است و چیزی برای تقسیم باقی نمی‌ماند.

### روی روتر (میکروتیک)

یک خط — بدونِ هیچ گواهی‌ای:

```
/interface ovpn-client add name=ovpn-pbx connect-to=ADDRESS-OF-SERVER port=1194 \
  protocol=tcp mode=ip user=router password=یک-رمزِ-بلند \
  certificate=none verify-server-certificate=no auth=sha1 cipher=aes256-cbc \
  add-default-route=no
```

آزموده‌شده روی RouterOS 7.25. همین ترکیب است که `ovpn-client` میکروتیک
واقعاً حرف می‌زند: TCP، sha1، aes256-cbc، نام و رمز بدونِ گواهیِ کلاینت.

`add-default-route=no` مهم است: وگرنه کلِ اینترنتِ روتر از تونل می‌رود.

### و ترافیکِ اپراتور از کدام خط بیرون برود

اگر روتر چند خط دارد و اپراتور فقط یکی‌شان را می‌شناسد (مثلاً سیم‌کارت)، روی
روتر:

```
/ip firewall address-list add list=voip.example address=203.0.113.0/24
/ip firewall mangle add chain=prerouting action=mark-routing \
  new-routing-mark=lte-route dst-address-list=voip.example passthrough=no
/ip route add dst-address=0.0.0.0/0 gateway=lte1 routing-table=lte-route
```

این قانون روی **مقصد** کار می‌کند نه مبدأ، پس ترافیکی که از تونل می‌آید را هم
می‌گیرد و لازم نیست چیزی برای تونل جدا نوشته شود.

---

## ⚠️ تله‌ای که یک ساعت وقت می‌گیرد

در `server.conf` شبکهٔ اپراتور **دو جا** باید بیاید:

```
route  203.0.113.0 255.255.255.0      # در جدولِ مسیرِ خودِ ماشین
```
```
iroute 203.0.113.0 255.255.255.0      # در tunnel/ccd/<نامِ کاربر>
```

اگر `iroute` نباشد، کرنل بسته را به `tun0` می‌دهد، OpenVPN دنبالِ کلاینتی
می‌گردد که صاحبِ آن آدرس باشد، پیدا نمی‌کند، و **بی‌صدا دورش می‌ریزد**.

اندازه‌گیری‌شده: سمتِ روتر فقط ۲۴ بستهٔ keepalive دیده بود و شمارندهٔ خودش برای
شبکهٔ اپراتور تکان نخورده بود. با یک خط `iroute` همان لحظه درست شد.

## بعد از بالا آمدن

آدرسِ تازه را به آستریسک بگو، وگرنه تماس‌ها وصل می‌شوند و یک طرف صدا ندارد:

```
Settings → Asterisk SIP Settings → NAT Settings
  External Address = آدرسی که اپراتور می‌بیند
```

و در ترانک، اگر اپراتور روی آدرسِ تونل تماس می‌فرستد:

```
media_address = همان آدرسِ تونل
```

`../doctor.sh` هر دو را می‌خواند و اگر خالی باشند می‌گوید.

## حالتِ «سرور زنگ می‌زند»

فقط وقتی سمتِ مقابل آدرسِ عمومی دارد و یک فایلِ `.ovpn` به تو داده است:

۱. آن فایل را `tunnel/client.ovpn` بگذار.
۲. در `.env`: `COMPOSE_PROFILES=tunnel`
۳. `docker compose up -d`

`client.ovpn.example` شکلش را نشان می‌دهد. هر دو حالت
`network_mode: service:freepbx` دارند، یعنی `tun0` داخلِ فضای شبکهٔ خودِ
کانتینرِ تلفن ساخته می‌شود و آستریسک آدرسِ تونل را مثلِ آدرسِ خودش می‌بیند —
بدونِ هیچ مسیریابی‌ای روی هاست.
